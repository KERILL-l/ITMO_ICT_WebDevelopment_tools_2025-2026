# Лабораторные работы

## Лабораторная 1

Сервис для управления хакатонами, командами, пользователями и их навыками. Реализован на FastAPI, с хранением данных в PostgreSQL.

### Структура проекта
- **app/** — основной код приложения
  - **main.py** — точка входа, инициализация FastAPI
  - **models.py** — модели данных (User, Hackathon, Team, Skill и связи между ними)
  - **schemas.py** — pydantic-схемы для валидации и сериализации
  - **api/** — роуты:
    - auth.py — регистрация/логин
    - users.py — работа с пользователями
    - hackathons.py — CRUD хакатонов
    - teams.py — CRUD команд и участников
    - skills.py — CRUD навыков
  - **core/** — конфиги, база, безопасность
- **alembic/** — миграции
- **docker-compose.yml** — запуск БД

### Основные функции
- Регистрация и авторизация пользователей (JWT, bcrypt)
- CRUD для пользователей, хакатонов, команд, навыков
- Добавление/удаление участников в команды
- Привязка навыков к пользователям
- Миграции через Alembic
- Документация и тестирование через Swagger

### Как делалось
1. Создал структуру проекта, настроил зависимости и docker-compose.
2. Описал модели и связи через SQLModel.
3. Реализовал роуты для всех сущностей, добавил авторизацию.
4. Настроил миграции и проверил работу через Swagger.

## Лабораторная 2

В этой лабораторной сравнивались подходы к параллелизму и асинхронности в Python на двух задачах:
- Суммирование большого диапазона чисел
- Парсинг веб-страниц и сохранение результатов в SQLite

### Структура
- **lab1/task1/** — суммирование (asyncio, multiprocessing, threading)
- **lab1/task2/** — парсер сайтов (asyncio, multiprocessing, threading)

### Описание функций
#### Task 1: Суммирование
- **async_sum.py** — делит диапазон на части, считает сумму асинхронно через asyncio.gather
- **multiprocessing_sum.py** — делит диапазон, считает сумму в нескольких процессах через multiprocessing.Pool
- **threading_sum.py** — делит диапазон, считает сумму в потоках, результат собирается в список

#### Task 2: Парсер
- **async_parser.py** — асинхронно скачивает страницы aiohttp, парсит title, пишет в SQLite
- **multiprocessing_parser.py** — каждый процесс скачивает и парсит страницу, пишет в SQLite
- **threading_parser.py** — каждый поток скачивает и парсит страницу, пишет в SQLite

### Как делалось
1. Для каждой задачи реализовал три варианта: asyncio, multiprocessing, threading.
2. Для парсера использовал aiohttp/requests и BeautifulSoup, результаты сохранял в SQLite.
3. Для суммирования и парсинга замерял время выполнения (см. скриншоты task1_img.png, task2_img.png).
4. Сравнил производительность подходов.

### Вывод
- Для суммирования разницы почти нет, GIL не мешает, но multiprocessing чуть медленнее из-за накладных расходов.
- Для парсинга async и threading быстрее multiprocessing, так как I/O-bound задача.
